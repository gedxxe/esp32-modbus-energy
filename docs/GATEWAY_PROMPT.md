# Development prompt for the separate ESP32-C6 gateway

**English** · [Bahasa Indonesia](id/GATEWAY_PROMPT.md) · [PTMP setup](LORA_PTMP.md) · [Wire contract](LORA_PROTOCOL.md)

Copy the prompt below into the **INPUT of a new coding-agent chat opened in the separate gateway repository**. It is a development request, not a Serial Monitor command and not a command for the S3 web console. Give that chat read access to this station repository or its source ZIP. Keep the node repository available as a reference rather than overwriting it with receiver firmware.

The prompt targets the station contract shipped in 3.4.1. Its wire version remains Energy Station v1, compatible with 3.4.0. Read the actual source and public vector when implementing the gateway. The older public HELLO fixture deliberately contains firmware text `3.4.0`, which does not change its protocol version.

## Prompt to copy

```text
Build a separate, compile-ready ESP32-C6 + SX1262 raw-LoRa PTMP gateway for the Midea Energy Station nodes. Implement the gateway in this repository. The ESP32-S3 node project is the read-only interoperability reference and must not become the gateway build target.

Start by reading these files from the supplied station source:
- docs/LORA_PROTOCOL.md and docs/LORA_PTMP.md
- firmware/include/lora_protocol.h
- firmware/include/checkpoint_log.h, energy.h and clock_guard.h
- firmware/lib/FortMeter/src/MeterProfiles.h
- firmware/src/lora_service.cpp
- docs/lora-v1-vector.json and tools/check_lora.py
- docs/LORA.md and docs/ENTERPRISE_WIFI.md

Inspect the exact C6 development board, radio module, available GPIOs, installed SDK and build tools before selecting wiring. Pin a compatible supported framework and RadioLib 7.8.1. The C6 application has one high-performance application core. Do not copy S3 core-1 affinity, PSRAM assumptions, GPIO assignments, OLED, Modbus polling or RGB/RMT setup. Produce a C6 pin table and generated SVG after checking the actual board/module. Keep RF-switch/TCXO configuration specific to that module. Do not infer that every SX1262 module has the Ra-01SH crystal and DIO2 switch circuit.

The topology is several independent S3 meter stations to one office C6 gateway, then Wi-Fi to a configurable backend. Use raw LoRa, not a LoRaWAN server/concentrator, mesh, broadcast-only receiver, text payload or JSON over RF. Default carrier is editable 915 MHz. Default PHY is 125 kHz, SF7, CR4/5, preamble 8, logical sync 0x12, explicit header, normal IQ and LoRa CRC. Match the node's RadioLib sync-byte semantics. Keep radio disabled until configured. Document applicable regional limits without silently changing the owner-selected default.

Implement a bounded gateway inventory, initially 16 entries with an explicit capacity constant. Each entry contains Network ID, unique Node ID, name, a nonzero 32-byte per-node key, enabled state and commissioning notes. Gateway ID defaults to 1, Network ID to 1, with example nodes 2, 3 and 4. Node and gateway addresses must differ. A station's local Modbus slave/profile/saved-meter IDs are payload metadata and must not be used as its radio source ID. Keys must not appear in logs, status JSON or browser storage. Provision new secrets through the protected local AP.

Implement the exact Energy Station v1 binary codec from the source, with explicit little-endian fields and no native-struct wire casts. Header is 24 bytes, payload at most 112, tag 16, total at most 152. Verify the first 16 bytes of HMAC-SHA256 over header plus payload in constant time before accepting data. Check magic, version, reserved bits, length, network, source, destination, session and expected type. Select the node key using a bounded lookup, and reject unknown/disabled nodes. HMAC authenticates the existing plaintext protocol, so do not silently introduce encryption or a new packet layout.

Support HELLO=1, ACK=2, TELEMETRY=3, POLL=4 and CHECKPOINT=5. For a node HELLO/telemetry/fragment, ACK swaps addresses, keeps its network and node session, echoes the exact sequence and has one payload byte containing the acknowledged type. Never create a gateway session in that ACK or increment its echoed sequence. Duplicate valid packets need another ACK without duplicate insertion. Wrong-node, wrong-session, wrong-type and malformed ACKs must not complete another transaction.

Maintain candidate/current session state per node. A correctly signed HELLO is a candidate, not sufficient proof of current reachability after replay or receiver reboot. ACK it, then issue a fresh correlated live POLL and confirm its authenticated response before replacing an established current session. Keep established data while a candidate is pending, rate-limit candidate work and reject stale data/session promotion. Preserve a monotonically increasing per-session gateway POLL sequence across gateway resets, using CRC-protected sequence-block reservations written before transmission. A node rejects replayed/decreasing poll sequences. Handle missing sequence state explicitly rather than guessing or resetting it to 1 for the same live session.

The radio owner must be a bounded, nonblocking worker. The ISR only records an IRQ flag. Return to RX after TX_DONE. Bound BUSY, reset/startup, ACK queues, retries and all network waits. One SX1262 can receive on one selected PHY and cannot receive while it transmits. Use one shared gateway airtime budget across every ACK and POLL. Prioritize ACKs, coalesce duplicate queued ACKs, expire obsolete work, and use round-robin fairness for optional node requests. Prefer passive periodic telemetry over redundant live polls. Run at most one checkpoint transfer globally, while admitting unrelated live uplinks between its fragments. Nodes still have autonomous uplinks, so central polling does not provide TDMA or a collision-free channel. Use actual frame airtime and leave headroom when calculating station intervals/capacity. The node ACK default is 10 seconds, its first-TX contention can reach 30 seconds, and a matching late ACK may be accepted during retry backoff only while that exact frame remains outstanding. Do not assume a polling deadline equals an ACK deadline.

Decode the 32-byte telemetry payload exactly, including request correlation, device UTC, sample age, validity flags, immutable profile ID, local saved-meter ID, WIB day, checkpoint revision and IEEE754 binary64 kWh. Keep missing/stale energy unavailable, never zero. Preserve gateway receive time separately from node time. Do not multiply CT/PT again. A telemetry value is not a scheduled checkpoint capture.

Implement POLL mode 0 for live telemetry and mode 1 for checkpoint days. A day of zero means the station's current capture day. The five-byte request contains mode plus little-endian day. Use the current node session and a fresh increasing POLL sequence. Match responses to network, node, session and correlated request. A missing day currently produces no fragments, so report timeout/unavailable rather than an empty successful record.

Reassemble CHECKPOINT fragments using the 12-byte fragment header, 100-byte maximum chunk and exact total 446. Accept out-of-order/duplicate bytes only when bounds and content agree. Retire partial transfers on session change or bounded timeout. A station can interleave its own live telemetry between archive fragments. Process that frame without resetting the correlated archive assembly. Reassemble one frozen image, ACK each accepted fragment, then run CRC and semantic validation matching checkpoint_log.h before publishing the day. Preserve the ten WIB schedule points, request/response timestamps, immutable recorded values and source/ratio IDs. Keep historical profile IDs intact. Use the supplied pure decoder and its dependencies where practical, retaining their GPL-3.0-only terms. Never backfill a missing point from a later telemetry value or recompute meter maps at the gateway.

Keep radio packet acceptance, locally durable collection and backend delivery as separate statuses. Use a recoverable CRC-protected local outbox with verified writes and bounded retention. Never format failed storage automatically. Do not call a transient queue entry durable. ACK is not a database-commit acknowledgement, and nodes retain records regardless of ACK. After a gateway crash, request the saved day again when necessary. Make backend ingestion idempotent using node/network, day/revision and captured-source identity, so retry cannot duplicate energy or overwrite a completed point with an older version. Define the backend payload/schema and configurable HTTPS endpoint without inventing a server URL or credentials. Backend absence must not block radio acquisition.

Provide local AP/client/dual configuration and Wi-Fi scanning without a hardcoded corporate SSID. Support Personal and optional PEAP/EAP-MSCHAPv2 through official APIs for the pinned SDK. Preserve server CA-chain/date validation, with the public CA bundle by default, optional private CA and optional certificate DNS constraint. Keep identity automatic from username unless explicitly edited. Never disable validation or require an unexplained mandatory certificate upload. New credentials go through the protected AP, and every form must show local submit/progress/error feedback. Provide a deliberate local clock-setting route before Enterprise/TLS if no trusted current time is available. Do not assume the gateway has a DS3231, that NVS contains current time or that SNTP can run before Wi-Fi authentication. Any radio time-bootstrap policy must authenticate and confirm a fresh authorized node first and be explicit.

Provide a compact English/Indonesian dashboard with node inventory, RF settings, session/pairing status, node time/receive age, values, checkpoint retrieval, outbox/backend state, RSSI/SNR, ACK/retry/auth/CRC counters and bounded logs. Distinguish configured, chip initialized, authenticated radio exchange, live-data freshness and database durability. Show measured metadata and label schematic animation honestly.

Complete verification before packaging: real C6 compile, public codec/HMAC vector, three independent nodes/keys, foreign-node and replay rejection, delayed/duplicate ACK handling, sequence reservation across reset, candidate-session challenge, concurrent telemetry during one archive transfer, fragment corruption/reordering, outbox power-loss faults, backend outage/idempotence, and actual generated-byte web tests for both languages. Document software mocks separately from pending RF/power tests. Deliver source, pinned dependencies, wiring SVG/netlist, protocol compatibility notes, setup steps and verified binaries with manifest. Do not claim field pairing, range or zero data loss without hardware evidence.
```

The gateway work should report its exact target, framework, source-contract version and completed checks. Its first hardware test should use one node before adding the other two. The [PTMP guide](LORA_PTMP.md) contains the operator-facing ID table and commissioning sequence.
