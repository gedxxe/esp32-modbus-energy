## Audit batas lintas modul

**Modbus/RS485:** Pertahankan manual-direction RS485 GPIO 17 (TX), 18 (RX), 16 (DE/RE), validasi CRC, batas waktu transaksi dan satu pemilik UART. Modul `FortTransport.h`/`ModbusMaster.cpp` dan pemetaan `MeterProfiles.h` dipakai bersama. Jangan mengubah scaling ADL400 (FC03 `0x0000` 2 register, CT/PT terpisah, `/100` sekali) hanya untuk menutupi kegagalan Wi-Fi. Masih perlu validasi bench masing-masing Fort, Habuer, ADL400, ACR, APM setelah flash.

**Perekaman dan pemulihan daya:** Jadwal checkpoint, RTC, immutability record, CRC dan generation-bank disimpan oleh modul terpisah (`checkpoint_log.h`, `capture_archive.h`, `settings_bank.h`, `clock_guard.h`). Audit ini **tidak** mengubah schema penyimpanan maupun penjadwalan, agar perubahan koneksi tidak merusak arsip. Uji pemadaman mendadak dan daya kembali tetap diperlukan sebelum pemasangan permanen.

**Enterprise 802.1X:** Adapter memakai **PEAP dengan MSCHAPv2**, tidak otomatis mendukung semua profil EAP perusahaan. Clock valid, CA root tepercaya (bundle publik atau CA privat yang diunggah), dan kebijakan RADIUS/NAC tetap wajib cocok. Nama DNS server RADIUS adalah penguatan keamanan yang disarankan; ketika tidak dikonfigurasi, akar sertifikat tanpa batasan hostname tidak setara dengan pinning server. ESP32-S3 hanya mendukung Wi-Fi **2,4 GHz**. Jangan mematikan pemeriksaan sertifikat untuk mengejar koneksi. UI/host test bukan bukti autentikasi ke RADIUS nyata.

**Jaringan dan fallback:** `network_attempt.h` dan `network_settings.h` sudah memiliki tahapan koneksi, batas autentikasi/DHCP, cooldown, AP cadangan, dan pemisahan penyimpanan settings core1 dari driver Wi-Fi core0. Kegagalan koneksi klien tidak boleh menghentikan akuisisi lokal. Jika ada perubahan SSID/kredensial pada network kantor, mulai melalui AP pemulihan; sesudah save, periksa **Connection result** dan IP DHCP, bukan hanya respons HTTP.

**LoRa PTMP:** Node SX1262 tetap raw LoRa 915 MHz default dapat diedit, protokol v1, addressed ACK/HMAC, CAD/backoff; receiver yang sesuai adalah firmware ESP32-C3 terpisah. Uji beberapa node di pabrik, delay ACK, hidden-node collision, power/range 400 m dan retransmisi arsip tidak dapat disimpulkan dari simulasi software.

**UI/API/diagnostik:** `web/request.js` membatasi satu permintaan aktif terhadap server HTTP sinkron; operasi POST tidak boleh dibatalkan demi polling. Diagnostik, scan serial dan perubahan pengaturan memiliki arbiter/batasan pada firmware. `firmware/src/main.cpp` sangat besar: pecah modul sebagai proyek terpisah setelah test hardware, bukan bersamaan dengan perbaikan Enterprise dan migrasi setting.

**Paparan jaringan:** Antarmuka pemulihan menggunakan HTTP lokal dan kredensial AP build-time, dan penyimpanan Preferences standar tidak otomatis terenkripsi. Batasi akses fisik/jaringan AP, tinjau perubahan kredensial AP untuk deployment, dan jangan memasukkan password ke laporan/log publik.

## Verifikasi dan gate rilis

Jalankan pada checkout branch audit (Node **24.22.1** untuk asset deterministik, PlatformIO dan toolchain sesuai `firmware/platformio.ini`):

```bash
python tools/security_audit.py --self-test
python tools/security_audit.py --current --history
python tools/generate_docs.py
python tools/check_docs.py
g++ -std=c++11 -Wall -Wextra -Werror -Ifirmware/test/network_stub -Ifirmware/include firmware/test/test_network.cpp firmware/src/enterprise_station.cpp -o /tmp/network-test
/tmp/network-test
npm ci
npm run check:web
npm run test:enterprise
pio run -d firmware
```

Tahap lapangan sebelum merge atau flash produksi: (1) Personal SSID A→B→A dengan password berganti; (2) PEAP SSID tersimpan → scan ulang → save tanpa kirim ulang secret; (3) PEAP SSID baru dengan login/CA baru dari AP; (4) profile PEAP salah metode/CA menunjukkan error tanpa loop; (5) boot AP-only tanpa OLED; (6) RTU kontinu dan checkpoint tetap jalan saat Wi-Fi gagal; (7) brownout dan pemulihan arsip; (8) LoRa ke gateway ESP32-C3 dalam topologi empat node.

**Batas kesimpulan:** Perubahan perangkat lunak dan pengujian host merupakan mitigasi yang dapat di-review, tetapi klaim *sudah berhasil tersambung Wi-Fi Enterprise perusahaan*, *Modbus/LoRa fisik stabil*, atau *power loss terjamin* tidak dibuat tanpa bukti perangkat nyata. Audit ini tidak mengubah `main` secara langsung; perubahan diajukan lewat Pull Request.
